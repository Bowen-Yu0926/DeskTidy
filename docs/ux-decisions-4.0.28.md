## 1. 四个必答语义问题

### Q1 多选双击语义（G5 / UX-F-12）
- 产品判定：**打开全部选中项**。
- 依据：DeskTidy 图标语义对齐 Windows 资源管理器（多选双击=打开所选全部）。分区是自定义容器，若只打开双击项，会让「先多选再双击」这一常见路径失去意义，且与菜单「打开」的选中数量文案不一致。取消多选不应作为双击的副作用——多选态应保持，便于继续打开下一组。
- 测试判定标准：选中 3 项，双击其中一项 → 3 个目标应用实例全部启动，且选中态不消失；双击未选中项 → 仅该项被选中并打开。不满足判 fail。
- 分级：缺失=明显不适，P2。

### Q2 宠物托管分页栏时的分页按钮形态（G11 / UX-P-06）
- 产品判定：**二者并存**。宠物气泡是分页的展示位，但浮标栏（page bar）窗口必须保留独立形态；宠物不可用（被移出屏幕、资源缺失、关闭）时分页入口仍可达。
- 依据：分页是主流程功能（G 分区导航），不能让其可用性单点依赖装饰性宠物；v4.0.28 已有「关闭宠物后分页按钮回归」的修复方向（9ba2434），说明设计上本就保留浮标栏。
- 测试判定标准：开启宠物 → 浮标栏窗口存在且分页芯片互不重叠；关闭宠物 → 浮标栏窗口仍存在、位于常规位置、点击可切页；宠物移出屏幕时同理。任一情况分页不可点判 fail。
- 分级：缺失=阻塞使用，P0。

### Q3 分区内图标重排（区内拖拽重排 / 自动换行 / 拖到边缘换行）（G3 / UX-F-04、UX-F-05）
- 产品判定：**自动换行应实现；手动拖拽重排待定；拖到边缘换行不应实现**。
- 依据：自动换行是布局正确性底线（否则分区变窄时图标重叠/溢出），且 v4.0.28 已有窄分区面板移动修复（bad0286）。手动重排需持久化排序模型且用户收益有限（文件管理器本身也不支持图标重排），判定待定，待收集实际投诉再定。边缘换行会引入视口滚动歧义，且与分区整体语义冲突，明确不做。
- 若实现自动换行的期望行为：按网格顺序（行优先）从左上排布；分区宽度不足以容纳一整行时允许部分折行；拖放过程中仅高亮目标分区，不在区内显示插入指示线。
- 测试判定标准：把分区宽度逐级缩至能容纳 1 列，任意宽度下图标不重叠、不越出分区底边、不与相邻分区图标交叠；不满足判 fail。重排/边缘换行不纳入本轮 pass/fail。
- 分级：自动换行缺失=阻塞使用，P0；手动重排=打磨项 P3（本轮不判）。

### Q4 批量操作部分失败的反馈（G4 / UX-F-10）
- 产品判定：**toast 汇总失败项 + 可撤销（成功项也需可恢复）**。禁止静默跳过。逐项弹窗在批量场景噪音过大，不采用。
- 依据：静默跳过会让用户误以为全部成功并丢失文件可信度；汇总 toast 在一次交互内给出失败数量与名称，且不阻断后续操作。
- 测试判定标准：构造 3 项批量操作其中 1 项失败（如目标只读/被占用）→ 出现 toast 明确写明失败数量并列出失败项名称，失败项留在原处、成功项已迁移；连续两次点击 toast 不重复堆积；提供「撤销」入口且撤销后全部项回到原位置。不满足判 fail。
- 分级：缺失=阻塞使用，P0。

## 2. G1~G12 逐条判定

| 编号 | 问题描述 | 产品判定 | 理由 | 测试判定标准（pass/fail） | 分级/优先级 |
|---|---|---|---|---|---|
| G1 | 拖放中途取消后是否残留幽灵图（UX-F-02） | 应实现 | 残留幽灵图会让用户误判文件已落位，是数据安全感知问题 | 按 Esc 或拖出分区取消后，桌面/分区内不得出现半透明残留图，下一次截图与操作前一致；有残留判 fail | 阻塞使用，P0 |
| G2 | 只读分区写入失败是否给 toast（UX-F-03） | 应实现 | 无提示的静默丢弃等于丢文件 | 向只读分区拖入文件 → 出现失败 toast（含分区名），源文件仍在原处，分区内无半写入图标；无提示判 fail | 阻塞使用，P0 |
| G3 | 分区内手动拖拽重排（UX-F-04） | 待定（自动换行见 Q3） | 需持久化排序模型，收益待验证 | 本轮不判 pass/fail；仅在自动换行正确时不得因未实现重排而判 fail | 打磨项 P3 |
| G4 | 批量部分失败反馈（UX-F-10） | 应实现，见 Q4 | 静默跳过=可信度问题 | 见 Q4 判定标准 | 阻塞使用，P0 |
| G5 | 双击打开默认程序 / 多选双击语义（UX-F-11、UX-F-12） | 应实现，语义见 Q1 | 核心打开路径 | 双击 .txt/.png/.docx 各启动对应默认程序且 DeskTidy 不抢焦点；无默认程序时弹「选择打开方式」；多选双击见 Q1 | 明显不适，P1 |
| G6 | 文件图标右键菜单是否反映选中数量（UX-F-14） | 应实现 | 菜单文案与选中态不一致会导致误批量删 | 右键多选后菜单删除项文案包含数量（如「删除 3 个项目」）；右键未选中项时先将其设为唯一选中；不一致判 fail | 明显不适，P1 |
| G7 | 拖出到外部第三方应用（UX-F-17） | 应实现 | 与 Explorer 的基础互通能力 | 拖到资源管理器成功复制且源保留；拖到无效目标按 Esc 无任何写入；一次拖出不得双写（目标目录文件数只增一份） | 明显不适，P1 |
| G8 | 删除确认对话框与回收站还原（UX-F-18） | 应实现 | 唯一数据安全兜底 | 删除前弹确认（含名称）且可取消；删除后回收站浮标可见该文件；从浮标还原后文件回到原分区原位置。缺确认或还原错位判 fail | 阻塞使用，P0 |
| G9 | 搜索结果定位与闪烁高亮（UX-F-19、UX-F-20） | 应实现 | 搜索的价值在于跳转到目标 | 双击结果项后目标图标滚动到可视区、所在分区自动翻页、闪烁高亮 ≥1s；结果已删除时提示并从列表移除 | 明显不适，P1 |
| G10 | 宠物拖动 / 贴边 / 双击（UX-P-02、03、05） | 应实现 | 宠物是可见装饰，拖不动=功能残缺 | 拖动宠物跟手无残影，松手位置持久化（重启保持）；拖至边缘 ≤100ms 吸附对齐且不越屏；双击进入专属姿态且与单击不冲突（两次间隔 ≥300ms 不误触） | 明显不适，P1 |
| G11 | 关闭宠物后分页按钮回归（UX-P-06） | 应实现，形态见 Q2 | 主流程不得依赖装饰性组件 | 见 Q2 判定标准 | 阻塞使用，P0 |
| G12 | 宠物设置快速连点竞态（UX-P-08） | 应实现 | 设置竞态已在本轮修复（9ba2434） | 1s 内连续切换宠物显示/气泡/大小 10 次：不崩溃，关闭后设置与 UI 状态一致，无重复气泡或穿透窗口残留 | 明显不适，P1 |

2. 本轮所有 P0/P1 项必须有明确 pass/fail 结论；标「待定」的 G3 记为 N/A 不计失败。
3. 判定基准文档为 docs/ux-decisions-4.0.28.md（本文），与 docs/ux-checklist-4.0.28.md 条款编号一一对应。
